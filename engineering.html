The async pipeline

The defining piece of distributed-systems work: a multi-tier Celery canvas over Redis with reliability and observability pushed down to per-task decorators. Results aren't passed via in-memory handles — every stage writes status to Postgres and clients poll, which is the right model for a long, fan-out workload with a progressive-fill UI.

Why it's hard

Picking the right primitive per stage

The inner chain(group(parallel_tasks, immutable=True), score.s()) guarantees every enrichment section persists before scoring runs — a clean chord-style barrier over heterogeneous tasks. Finalization derives terminal status from child reports (a no-op while any child is still pending, so it's race-safe), then ranks survivors and assigns order.

Reliability engineering

At-least-once, idempotent, row-locked

Nearly every task is acks_late with bounded retries, so redelivery survives worker crashes. Idempotency is pervasive: entry tasks short-circuit on terminal or in-progress status, and creation paths use select_for_update + get_or_create catching unique-violation races. Control tasks revoke-on-error to prevent retry storms, and a single failed report degrades rather than failing the whole pipeline.

Domain & data model

~36 models and ~98 migrations built around two hubs — a Company and a Report — with a deliberate, consistent modeling discipline.

  • Explicit through-models everywhere. Every domain many-to-many carries data on the relationship itself — classification role, ownership/title, competitor distance, pipeline tier/order, debtor vs. secured-party — rather than bare many-to-many fields.
  • A shared abstract base gives every entity a UUID primary key plus created/updated audit timestamps.
  • Real geometry & advanced Postgres. PostGIS across locations, regions, and trade areas; JSON and array fields; 12 multi-column unique constraints; partial/composite indexes; and custom managers running window-function YoY-growth and location-quotient queries.
  • A separate ~230-column firmographics feed modeled in its own app and bridged into core models with type-coercion guards.

~10 integrations behind one abstraction

Each external source sits behind a uniform retriever/service interface with its own retry, logging, and API-cost accounting — firmographics and financials, behavioral foot traffic, search and news, corporate officers, Census/ACS, BLS/BEA economics, geocoding, and cloud storage.

  • Async job lifecycle. The foot-traffic integration builds a geofence, submits an async report job, and polls to completion with linear backoff — accounting for data lag and latest-complete-quarter logic.
  • Fuzzy cross-source entity resolution. A normalization layer (business-suffix stripping, address canonicalization, Unicode cleanup) feeds fuzzy matching that converges heterogeneous sources onto one canonical company or person.
  • Multi-state public-records ingestion. A scraper fleet behind a dispatcher (clean APIs where they exist, browser automation where they don't) normalizes secured-loan filings and derives the engagement windows the product is built around.

Infrastructure, observability & testing

  • Containerized GIS stack. A slim Python image builds the full GDAL/GEOS/PROJ toolchain, runs as a non-root user, and bakes in commit/branch build args for traceability. Compose orchestrates web, Redis, Celery (3 replicas), Flower, and a PostGIS database with health-gated startup ordering.
  • End-to-end request correlation. A request ID is threaded from HTTP through middleware into Celery task headers and JSON logs. A custom Slack handler posts Block-Kit error alerts with IDs, tracebacks, and auto-generated cloud-logging deep links; a statsd client emits request and task-lifecycle metrics.
  • Marker-driven test pyramid. pytest with seven markers and -m "not external" by default, so CI never hits paid model or data APIs; factory-boy + Faker factories and mock fixtures back ~30 test files across models, views, tasks, and analytics.
  • A codified quality bar. Ruff with ~45 rule families — including bandit security scanning, bugbear, timezone-aware datetime checks, and a McCabe complexity ceiling — enforced by a pre-commit hook and in CI.

Data quality

Company/person entity resolution under concurrency

Normalization plus fuzzy matching across sources, resolved under select_for_update + get_or_create with explicit integrity-error handling, so concurrent workers converge on one canonical row — the duplicate-company hotfix.

FinOps & lifecycle

Cost tracking, audit trail & report refresh

Token-level model-cost tracking into a polymorphic usage log plus an archival audit trail; and a report-expiration and subscription-refresh subsystem with vintage grace-window logic that auto-regenerates stale reports and notifies subscribers.

Alongside that: later carrying the codebase through a Django 5.1 / Python 3.12 upgrade, the strict Ruff ruleset and test harness, production observability (the Slack handler, statsd client, and request-ID propagation), and a pipeline-latency pass that returned the API response before the async chain runs and killed N+1 queries with select_related.

What this proves

This is a revenue-bearing system with operational maturity most backends lack — and the genuinely hard parts are the interesting ones: choosing the right async primitive per stage, derive-status-from-children finalization that's race-safe, at-least-once semantics with idempotent writes, fuzzy entity resolution across ~10 sources, and a real geospatial engine composing clustering, concave hulls, and spline smoothing into PostGIS geometry. Those fundamentals are exactly what I'd apply today.
