The AI inside

The defining trait isn't a single clever prompt — it's breadth of constrained generation. Around 15 distinct analyses, each backed by an externalized prompt and a validated output schema, with capability-based provider routing, a compositional prompt system, and a token-level cost-and-audit ledger behind every call.

Schema-first, not free text

Nearly every analysis defines a Pydantic schema wrapped in a guard, so the model's output is a typed, validated contract before it can reach the database. A hallucinated or malformed field is caught at the boundary — only validated output is ever persisted.

The schemas are genuinely expressive: enum-constrained business-state outcomes, fixed/variable and direct/indirect cost taxonomies, nested polymorphic shapes (a customer-base report with optional consumer/commercial/hybrid branches), URL validation on news links, and a custom field validator with a negative-lookahead regex that rejects outputs containing literal headers — pushing formatting constraints into validation rather than into prose.

Capability-based provider routing

Two providers, routed by what the task actually needs — reasoning over in-hand context, or live web retrieval. Models are aliased for indirection so a routing decision isn't hard-coded to a vendor string.

Route by capability, not by habit

In-context reasoning summarization · classification · structured cost & risk analyses
Web-grounded retrieval owner profiles · customer base · regulatory · news

The web-grounded path surfaces citations and a per-call response cost, both of which are stitched back into every result and the cost ledger.

Two structured-generation patterns

Pattern 01 · Guard as validator

Validate over the web-grounded client

For retrieval tasks the guard wraps the retriever call and returns validated output — live web answers are forced to conform to the schema before anything downstream sees them.

Pattern 02 · Function-calling

Schema-as-tool, forced tool choice

For in-context tasks the schema is compiled into a function-calling tool with required tool choice, so the model must return a structured object rather than prose. Same guarantee, different mechanism — chosen per provider.

A real prompt-engineering system

Prompts are fully externalized as a versioned markdown library, loaded by a one-line helper with string-format injection — not string literals scattered through the code. The library is scenario-branched: owner-profile selects with/without-name variants; customer base selects consumer/commercial/hybrid; cost-driver and regulatory carry default/full/simple versions.

A subtle but important touch: numeric features are first mapped to ordinal English descriptors — "robust positive growth", "severe contraction" — via lookup tables before injection, so the model reasons over qualitative language rather than raw floats.

Retrieval & grounding

A clean strategy/factory pattern abstracts retrieval behind one interface with several concrete strategies (in-context, web-grounded, search with pagination + recency stop-criteria, and a news API).

  • Three-source parallel news fan-out across a documented fallback chain, run concurrently with a thread pool, full-text scraping each article.
  • Scored, not just retrieved. Each article gets a 1–5 sentiment score with rationale and a yes/no relevance classification against a schema — supporting adverse-media due diligence.
  • Citations stitched through every web-grounded result so a claim can be traced back to a source.

Observability & FinOps

Two layers make the AI auditable and its unit economics legible — the part that turns a demo into a production system.

Audit trail

Full prompt/IO lineage to cloud storage

A decorator captures the in-scope prompt and writes three blobs per call — input, prompt, and output with citations and token usage — under a company/date/task path. Every generation is reproducible after the fact.

Cost ledger

Per-report unit economics

Every call emits a usage-log row (a generic foreign key to the report or pipeline, with token counts) and the system computes per-report and per-pipeline average cost and monthly trends against a rate card — token-level FinOps, not a monthly vendor invoice.

Why this is the production pattern

Schema-first discipline at scale, compositional multi-fragment prompt assembly, capability-based provider routing, a tracing-based prompt/IO audit trail, and a token-level cost ledger — with the deterministic scoring kept deliberately separate so the AI explains while math decides. That separation, and the validation boundary around every generation, is what makes model output safe to put in front of a credit committee.
